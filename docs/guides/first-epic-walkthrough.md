# First Epic Walkthrough / 第一個 Epic 實戰

> A hands-on guide to building a complete feature on the Next.js app. Estimated time: **~30 minutes**.
> 雙語：**[English below](#what-youll-build)** · **[繁體中文](zh-TW/first-epic-walkthrough.md)**

## What you'll build

A small **Notes** feature, end to end, mirroring the canonical `items` reference
(`next-app/lib/schema/items.ts` + `lib/validations/items.ts` + `actions/items.ts` +
`app/(dashboard)/dashboard/items/`). By the end you'll have touched every layer of the stack:

| Layer | File | What it does |
|-------|------|--------------|
| Schema | `lib/schema/notes.ts` | Drizzle table (`pgTable`) |
| Validation | `lib/validations/notes.ts` | Shared Zod schema |
| Mutations | `actions/notes.ts` | Server Actions (`"use server"`) + RBAC guard |
| Page | `app/(dashboard)/dashboard/notes/page.tsx` | Server Component that fetches + renders |
| Migration | `drizzle/migrations/*.sql` | Generated by `pnpm db:generate` |

### Prerequisites

- Completed the [Quickstart](quickstart.md) (the app runs at http://localhost:3000)
- Commands below run from `next-app/`

If you're using Claude Code, the Athena agent team builds this for you:

```bash
/athena:spec "notes feature: a per-user notes table with title + body, editor-and-above
              can create/edit/delete, a dashboard list page"
# → @spec-writer writes a feature spec (Drizzle schema + Zod + Server Action
#   signatures + RBAC) into docs/epics/ — this is NOT an OpenAPI contract.

/athena:implement     # TDD red → green → refactor (@dba reviews the drizzle-kit migration)
/athena:qa            # @reviewer + @qa + @evaluator: review + Vitest/Playwright + coverage
/athena:ship          # review → fix → commit → PR
```

Each step is one move in the **spec → implement → qa → commit → merge** pipeline. To advance
one step at a time and checkpoint between them, use `/athena:loop`.

The rest of this guide does it **by hand** so you understand what those agents generate.

## Option B — by hand

### 1. Define the Drizzle table

Create `next-app/lib/schema/notes.ts` (copy the shape of `lib/schema/items.ts`):

```ts
import { index, pgTable, text, timestamp, uuid } from "drizzle-orm/pg-core"

import { usersTable } from "./auth"

export const notesTable = pgTable(
  "notes",
  {
    id: uuid("id").primaryKey().defaultRandom(),
    title: text("title").notNull(),
    body: text("body").notNull().default(""),
    userId: uuid("user_id")
      .notNull()
      .references(() => usersTable.id, { onDelete: "cascade" }),
    createdAt: timestamp("created_at", { mode: "date" }).notNull().defaultNow(),
    updatedAt: timestamp("updated_at", { mode: "date" }).notNull().defaultNow(),
  },
  (t) => [index("notes_user_id_idx").on(t.userId)],
)

export type Note = typeof notesTable.$inferSelect
```

Export it from `lib/schema/index.ts` so `db` and migrations pick it up:

```ts
export * from "./notes"
```

### 2. Generate + apply the migration

```bash
pnpm db:generate     # drizzle-kit reads the schema → writes drizzle/migrations/000N_*.sql
pnpm db:migrate      # applies it to your local Postgres
```

> Never hand-write SQL DDL — let `drizzle-kit` generate the migration from the schema.
> The `@dba` agent reviews these migrations during the pipeline.

### 3. Write the shared Zod schema

Create `next-app/lib/validations/notes.ts` — this is the single source of truth for input shape:

```ts
import { z } from "zod"

export const createNoteSchema = z.object({
  title: z.string().min(1, "請輸入標題").max(255, "標題過長"),
  body: z.string().max(10_000).default(""),
})

export type CreateNoteInput = z.infer<typeof createNoteSchema>
```

### 4. Write the Server Action (with RBAC)

Create `next-app/actions/notes.ts`. Mutations are Server Actions guarded by
`requireEditor()` — viewers are read-only:

```ts
"use server"

import { db } from "@/lib/db"
import { notesTable } from "@/lib/schema"
import { requireEditor } from "@/lib/permissions"
import { createNoteSchema } from "@/lib/validations/notes"
import { revalidatePath } from "next/cache"

type State = { error?: string } | null

export async function createNote(prevState: State, formData: FormData): Promise<State> {
  // requireEditor() redirects viewers away — RBAC re-reads the role from the DB.
  const session = await requireEditor()

  const parsed = createNoteSchema.safeParse({
    title: formData.get("title"),
    body: formData.get("body") ?? "",
  })
  if (!parsed.success) {
    return { error: parsed.error.issues[0]?.message ?? "輸入無效" }
  }

  await db.insert(notesTable).values({ ...parsed.data, userId: session.user.id })

  revalidatePath("/dashboard/notes")
  return null // success — the modal closes + the list revalidates
}
```

> The Server Action **returns success (no `redirect`)** so a modal can close and the list
> refreshes via `revalidatePath` + `router.refresh()` (the CRUD-modal convention, E273).

### 5. Add the dashboard page

Create `next-app/app/(dashboard)/dashboard/notes/page.tsx` — a Server Component that fetches
directly (the folder *is* the route, App Router):

```tsx
import { db } from "@/lib/db"
import { notesTable } from "@/lib/schema"
import { requireAuth } from "@/lib/permissions"
import { eq } from "drizzle-orm"

export default async function NotesPage() {
  const session = await requireAuth()
  const notes = await db.select().from(notesTable).where(eq(notesTable.userId, session.user.id))

  return (
    <div className="space-y-4">
      <h1 className="text-2xl font-semibold">Notes</h1>
      {/* List with the reusable <DataTable> + a shadcn Dialog for create/edit.
          Copy app/(dashboard)/dashboard/items/_items-table.tsx and _item-dialog.tsx. */}
      <ul>
        {notes.map((n) => (
          <li key={n.id}>{n.title}</li>
        ))}
      </ul>
    </div>
  )
}
```

For the modal form + table, copy the `items` client components
(`_item-dialog.tsx`, `_item-form.tsx`, `_items-table.tsx`) and swap in your action and columns.

### 6. Test it

```bash
pnpm typecheck && pnpm lint
pnpm test                 # add a Vitest test for createNoteSchema, like lib/validations/*.test.ts
pnpm dev                  # sign in as editor@example.com and create a note; sign in as
                          # viewer@example.com and confirm you cannot
```

### 7. Gate + ship

```bash
scripts/pre-merge-check.sh        # repo hygiene + typecheck + lint + unit (add --e2e for Playwright)
```

Then commit on a feature branch and open a PR (`feat(E<n>): notes feature`). See
[CONTRIBUTING.md](../../CONTRIBUTING.md) for branch naming and the quality gate.

## What you learned

- The full **spec → implement → qa → commit → merge** pipeline
- A feature is co-located files: **Drizzle table → Zod → Server Action → page → migration**
- **RBAC** runs in the Server Action (`requireEditor()`), re-reading the role from the DB
- **App Router** routing: the folder under `app/(dashboard)/dashboard/` is the route
- Mutations use **Server Actions** that return success (no redirect) for the modal convention
