# E11 — OpenAPI Split

> **Size**: S (~1 session) | **Depends on**: E5 (Sessions endpoints stable)
> **Status**: spec

---

## Overview

Split the monolithic `docs/openapi.yaml` (1443 lines, 25 paths, 22 schemas) into domain-based modules under `docs/openapi/`. Entry file stays under 80 lines with `$ref` pointers. Zero functional change — pure structural refactor.

## No Code Changes

This epic touches only `docs/openapi/` files and the `generate:types` script. No server or client code changes.

## Current Structure

Single file `docs/openapi.yaml` with 7 domain groups:
- **auth** (8 paths): register, login, logout, refresh, forgot-password, reset-password, request-verify-token, verify
- **social** (4 paths): google/authorize, google/callback, github/authorize, github/callback
- **users** (2 paths): /users/me, /users/{id}
- **sessions** (2 paths): /users/me/sessions, /users/me/sessions/{session_id}
- **places** (3 paths): /places, /places/nearby, /places/{place_id}
- **portfolios** (6 paths): CRUD + places sub-resource + analytics
- **health** (1 path): /health

22 schemas + 3 reusable responses.

## Target Structure

```
docs/
  openapi.yaml              ← kept as symlink/copy for backwards compat (optional)
  openapi/
    openapi.yaml             ← entry file (~80 lines, $ref pointers only)
    paths/
      auth.yaml              ← 8 auth paths
      social.yaml            ← 4 OAuth paths
      users.yaml             ← 2 user paths
      sessions.yaml          ← 2 session paths
      places.yaml            ← 3 place paths
      portfolios.yaml        ← 6 portfolio paths
      health.yaml            ← 1 health path
    schemas/
      common.yaml            ← ErrorDetail, reusable responses, bearerAuth
      auth.yaml              ← UserRead, UserCreate, UserUpdate, BearerResponse, RefreshTokenRequest, ForgotPasswordRequest, ResetPasswordRequest
      user.yaml              ← (UserRead shared with auth — $ref from auth.yaml)
      session.yaml           ← SessionRead
      place.yaml             ← PlaceCreate, PlaceRead, PlaceUpdate, PaginatedPlaceResponse
      portfolio.yaml         ← PortfolioCreate, PortfolioRead, PortfolioDetail, PortfolioUpdate, PaginatedPortfolioResponse, PortfolioPlaceCreate, PortfolioPlaceRead, PortfolioPlaceUpdate, PortfolioAnalytics
      health.yaml            ← HealthResponse
```

## Entry File Design

`docs/openapi/openapi.yaml` contains:
- `openapi`, `info`, `servers`, `tags`, `security` (inline — small)
- `paths` section: each path key uses `$ref` to `paths/{domain}.yaml#/~1path~1name`
- `components/schemas`: each schema uses `$ref` to `schemas/{domain}.yaml#/SchemaName`
- `components/securitySchemes`: inline (3 lines)
- `components/responses`: `$ref` to `schemas/common.yaml#/responses/...`

## Toolchain Changes

### 1. Install @redocly/cli
```bash
pnpm add -D @redocly/cli --filter client
```

### 2. Add bundle script
In `client/package.json`:
```json
"openapi:bundle": "redocly bundle ../docs/openapi/openapi.yaml -o ../docs/openapi.bundled.yaml",
"generate:types": "redocly bundle ../docs/openapi/openapi.yaml -o /tmp/openapi-bundled.yaml && openapi-typescript /tmp/openapi-bundled.yaml --output src/api/types.ts"
```

### 3. Validate roundtrip
After split: `redocly bundle` → output must be semantically identical to current `docs/openapi.yaml`.

### 4. Backwards compatibility
Keep `docs/openapi.yaml` as the bundled output (regenerated by `pnpm openapi:bundle`). This ensures:
- Existing tools that read `docs/openapi.yaml` still work
- The split files in `docs/openapi/` are the **source of truth**
- CI can validate: bundle → diff → fail if drift detected

## $ref Convention

Path files use relative `$ref` for schemas:
```yaml
# In paths/auth.yaml
$ref: '../schemas/auth.yaml#/UserCreate'
```

Schema files use relative `$ref` for shared types:
```yaml
# In schemas/place.yaml
$ref: './common.yaml#/ErrorDetail'
```
