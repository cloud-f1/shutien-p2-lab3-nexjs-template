# E21 — Interactive Site Builder CLI

> **Size**: M (1-2 sessions) | **Depends on**: none
> **Status**: pending

---

## Goal

Build a Node CLI tool (`scripts/new-site.sh` wrapper + `@clack/prompts` interactive wizard) that guides users through bootstrapping a new site from this template — checking prerequisites, collecting project config, scaffolding files, and recording each step in a YAML build manifest.

## Problem Statement

Currently, onboarding a new project from this template requires manually:
1. Cloning the repo and renaming directories
2. Installing Python 3.12, Node 20+, pnpm, uv, PostgreSQL
3. Setting up `.env` files with correct variables
4. Running migrations, generating types, verifying the dev server
5. Customizing branding (theme, logo, app name)

There is no guided process, no prerequisite validation, and no record of what was configured. New users (or the user's future self) must read scattered docs to get started.

## Solution: Node CLI with @clack/prompts

### Why Node CLI over Shell Script

| Criteria | Shell Script | Node CLI (@clack/prompts) |
|----------|-------------|--------------------------|
| Cross-platform | macOS/Linux only | macOS/Linux/WSL |
| Interactive UX | Basic `read -p` | Spinners, multi-select, confirm, grouping |
| Error handling | Fragile | Try/catch, structured |
| Testability | Hard | Vitest-compatible |
| Dependency | bash | Node (already required) |

### CLI Workflow

```
npx new-site
  │
  ├─ 1. Welcome + prerequisite check
  │     ├─ Node >= 20        ✓/✗ (with install guidance)
  │     ├─ pnpm              ✓/✗
  │     ├─ Python >= 3.12    ✓/✗
  │     ├─ uv                ✓/✗
  │     ├─ PostgreSQL        ✓/✗
  │     └─ git               ✓/✗
  │
  ├─ 2. Project configuration (interactive prompts)
  │     ├─ Project name (slug)
  │     ├─ Display name
  │     ├─ Description
  │     ├─ Author name + email
  │     ├─ Database name
  │     ├─ Default theme (dark/indigo/navy/sage)
  │     ├─ OAuth providers (Google/GitHub/none)
  │     ├─ Domain features to keep (Places/Portfolio/both/none)
  │     └─ Deploy target (Zeabur/Docker/manual)
  │
  ├─ 3. Scaffold
  │     ├─ Copy template files
  │     ├─ Rename references (ai-coding-template → project slug)
  │     ├─ Generate .env from answers
  │     ├─ Generate .env.example (secrets redacted)
  │     ├─ Update package.json name/description
  │     ├─ Update pyproject.toml name/description
  │     └─ Remove unused domain code if deselected
  │
  ├─ 4. Setup
  │     ├─ pnpm install
  │     ├─ uv sync
  │     ├─ createdb (if PostgreSQL available)
  │     ├─ alembic upgrade head
  │     ├─ pnpm generate:types
  │     └─ Verify dev server starts
  │
  ├─ 5. Build manifest
  │     └─ Write .build-manifest.yaml with all answers + timestamps
  │
  └─ 6. Next steps summary
        ├─ "Run `make dev` to start"
        ├─ "Edit docs/openapi.yaml to add your first endpoint"
        └─ "Run `/athena:loop` to begin your first epic"
```

## Technical Design

### File Structure

```
scripts/
  new-site/
    index.ts          CLI entry point
    prompts.ts        @clack/prompts question groups
    checks.ts         Prerequisite validation (semver compare)
    scaffold.ts       File copy + template variable replacement
    setup.ts          Install + migrate + verify
    manifest.ts       YAML build manifest writer
    types.ts          Shared types (ProjectConfig, StepResult)
  new-site.sh         Thin wrapper: npx tsx scripts/new-site/index.ts
```

### Dependencies

```json
{
  "@clack/prompts": "^0.10",
  "yaml": "^2.7",
  "semver": "^7.6",
  "tsx": "^4.19"
}
```

### Prerequisite Check Logic

Each check returns `{ name, required, found, pass }`:
- `node`: `node --version` → semver compare >= 20.0.0
- `pnpm`: `pnpm --version` → any version
- `python`: `python3 --version` → semver compare >= 3.12.0
- `uv`: `uv --version` → any version
- `postgresql`: `pg_config --version` or `psql --version` → any version
- `git`: `git --version` → any version

Failed checks show install guidance (brew/apt/official docs link) but don't block — user can skip and fix later.

### Scaffold Strategy

Template variables use `{{PLACEHOLDER}}` syntax:
- `{{PROJECT_SLUG}}` → project name (kebab-case)
- `{{PROJECT_DISPLAY}}` → display name
- `{{DB_NAME}}` → database name
- `{{AUTHOR}}` → author string

Files to process: `.env.example`, `package.json`, `pyproject.toml`, `docker-compose.yml`, `zbpack.json`, `CLAUDE.md`.

### Domain Feature Removal

If user deselects "Places":
- Remove `server/app/models/place.py`, `server/app/api/v1/endpoints/places.py`
- Remove `client/src/pages/places/`, `client/src/hooks/usePlaces.ts`
- Remove corresponding Alembic migration, OpenAPI paths, MSW handlers

Similarly for "Portfolio" (which also removes Recharts dependency).

## Acceptance Criteria

- [ ] `npx tsx scripts/new-site/index.ts` launches interactive wizard
- [ ] All 6 prerequisites checked with version comparison
- [ ] Failed prereqs show platform-specific install guidance
- [ ] Project config collected via @clack/prompts (name, theme, OAuth, domains, deploy)
- [ ] Files scaffolded with template variables replaced
- [ ] `.build-manifest.yaml` written with all config + step timestamps
- [ ] Domain features can be deselected (removes corresponding code)
- [ ] `scripts/new-site.sh` wrapper works as shortcut
- [ ] Unit tests for checks, scaffold, manifest (>=80% coverage)
- [ ] Next steps summary printed on completion

## Risk Notes

- **Cross-platform edge cases**: Windows paths, PowerShell `python` vs `python3`. Mitigate: WSL recommended, document Windows limitations.
- **Template drift**: As the template evolves, scaffold logic must be updated. Mitigate: Use `.build-manifest.yaml` to detect template version.
- **Alembic migration removal**: Removing domain migrations requires careful dependency ordering. Mitigate: Only remove leaf migrations, warn if chain detected.
