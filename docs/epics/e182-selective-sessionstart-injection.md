# E182 — Selective SessionStart Injection (cued recall)

> Phase 45 — Memory Mechanism Maturity | Size: M (4 SP) | Deps: E180

## Problem

Today's SessionStart hook (`scripts/hooks/session-start.sh:48–52`) injects exactly one Tier 0 file: `~/.claude/template-memory/NEW_PROJECT_PRIMER.md` (~128 lines, kept under 100 by `@memory-curator`). The PRIMER is curated and load-bearing — that part works. But the underlying 7 category files (`failure-patterns.md`, `architecture-lessons.md`, `testing-patterns.md`, `anti-patterns.md`, `security-learnings.md`, `integration-gotchas.md`, `performance-insights.md`) are **never injected** at all. They live in Tier 0 but only `@memory-curator` reads them.

The PRIMER is a digest. It loses the long-tail. A session deep in `server/auth/` should also see specific lessons from `security-learnings.md` and `failure-patterns.md` — but does not.

Cued recall (Ebbinghaus): retrieval is more effective when the cue matches the context. Use the active branch's changed files to **augment** (not replace) the PRIMER with targeted excerpts from the underlying category files.

## Solution

Two-block inject:

**Block A — Always-on PRIMER** (unchanged from today): `cat NEW_PROJECT_PRIMER.md`. The curated digest stays the bedrock. Do not regress its UX.

**Block B — Cued category excerpts** (new): scan the 7 underlying category files; for each H2 section (lesson) whose `tags`/`domains` match the active branch, inject the section. Cap Block B at 150 lines.

1. SessionStart computes the active context cue:
   - `git diff --name-only main` — branch's changed files
   - `git status -s` — staged/unstaged
   - HEAD subject line of the latest commit
2. Tag-match each H2 section's frontmatter (E181 file-level + per-section override) against the cue's inferred tags/domains.
3. Inject Block B sections, ranked, until the 150-line budget is consumed. Prepend a one-line label `--- Tier 0 Cued (branch-targeted lessons) ---`.
4. Always-on `session-summary.md`, `epic-progress.md`, `git log -10` blocks remain unchanged.

### Tag schema (extends E181 frontmatter)

E182 adds two fields. File-level frontmatter applies to all H2 sections; per-section override allowed via inline frontmatter (rare).

```yaml
---
# Set by E181
strength: 0.72
half_life_days: 90
# Added by E182
tags: [server, auth, alembic]   # free-form, manually curated
domains: [server/]              # path-prefix list — matches against `git diff --name-only`
---
```

Tag/domain assignment lives with `@memory-curator` at promotion (E185 sets half-life; same workflow extends to tags/domains here).

### Match algorithm (ranked)

```
score(lesson, branch_files) =
  + 3 * |lesson.domains ∩ branch_path_prefixes|
  + 2 * |lesson.tags ∩ inferred_tags(branch_files)|
  + 1 * lesson.strength      # tie-break by usefulness
```

Top N until 200-line budget consumed. Always-inject set: lessons tagged `evergreen` (e.g. anti-patterns) bypass scoring.

## Implementation

1. Extend the E181 frontmatter migration with `tags` and `domains` (manual classification of the 15 existing files).
2. Author `match.sh` and `inject.sh` with the scoring algorithm above.
3. Replace SessionStart's `cat NEW_PROJECT_PRIMER.md` with `inject.sh` invocation.
4. Add fixture test: synthetic branch touching `server/auth/` → only auth/server-tagged lessons inject.
5. Add fixture test: empty git status (initial clone) → fall back to bulk inject.
6. Emit `tier0_loaded` (E180) for every selected lesson — preserves the retrieval signal.

## Out of Scope

- **Semantic match** (embeddings) — keyword/path-prefix only; LLM-side embeddings are too expensive to run on every SessionStart.
- **Branch-name matching** — only diff/status drives the cue. Branch names are too noisy.
- **Cross-project cue sharing** — strictly local.
- **Auto-tagging on promotion** — @memory-curator (E185) assigns tags manually; auto-classification is a follow-up.
