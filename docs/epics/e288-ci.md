# E288 — GitHub Actions CI

## Problem

The repo has no `.github/workflows/` directory. All quality gates (typecheck, lint, test, build,
DB migration) run manually today, which means regressions can land on `main` undetected.

## Solution

Add a single `ci.yml` workflow triggered on `pull_request` and `push to main` with two jobs:

- **quality** — typecheck + lint + unit tests + production build (placeholder env vars so
  `lib/db.ts` lazy-init and Auth.js don't fail at build time per `nextjs-saas-patterns §6`).
- **db** — fresh Postgres 16 service container; runs `pnpm db:test-migrate` to verify migrations
  apply cleanly against an empty DB.

E2e (Playwright) is **omitted** from CI for now: it requires a running Next.js dev server + seeded
DB and is too flaky as a blocking gate without a dedicated test environment. See Out-of-scope.

## Key Files

| File | Purpose |
|---|---|
| `.github/workflows/ci.yml` | New CI workflow |
| `next-app/package.json` | Script names verified: `typecheck`, `lint`, `test`, `build`, `db:test-migrate` |
| `README.md` | CI status badge added |

## Acceptance Criteria

1. `.github/workflows/ci.yml` exists and is valid YAML.
2. `quality` job: checkout → pnpm setup → install (`--frozen-lockfile`) → `pnpm typecheck` → `pnpm lint` → `pnpm test` → `pnpm build` (with `DATABASE_URL` + `AUTH_SECRET` build-time placeholders).
3. `db` job: Postgres 16 service with health-check → install → `pnpm db:test-migrate` with real `DATABASE_URL`.
4. All script names match `next-app/package.json` exactly.
5. Action versions are pinned (SHA or `@v4`-style).
6. Local QA passes: `pnpm typecheck && pnpm lint && pnpm test && pnpm build`.
7. README.md has a CI status badge.

## Out of Scope

- Playwright e2e job (unreliable without dedicated infra — track separately).
- Deploy/publish job.
- Cache invalidation strategies beyond pnpm's built-in store cache.
