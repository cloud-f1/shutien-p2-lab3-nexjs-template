Epic Pipeline — plan → merge

這頁強調兩件事：(1) 人類只在兩個點介入 — 開頭核准 plan、結尾 review PR；(2) 失敗不是死路 — debugger loop 自動把控制權交回 implement。底下的 step matrix 是 epic-progress.md 的視覺化，Rule #18 就是看這張表來判斷能不能 Stop。

Stop Verifier — 20 條防線

這頁是「為什麼 Learning Loop 有牙齒」的具體展示。20 條 rule 不用唸，重點是右下角 callout — Rule #18 把 epic-progress.md 的 qa 欄位接到 Stop hook，這就把「跳過測試」這件事變成機械上不可能。

Metrics + Evaluator

/athena:metrics (E146)

從 .claude/audit.jsonl 彙整每個 agent 的執行次數、成功率、平均時長、retry 數。

可靠度是可量測的，不是感覺。

@evaluator (E147)

獨立驗收 agent — 不寫碼、不審碼，只驗「spec 要求的 acceptance criteria 有沒有達成」。

避免「寫的人也是驗的人」的 conflict of interest。

metrics + evaluator 是最新的 E146/E147。量測 + 獨立驗收是可信賴 agent 的最後一哩。
