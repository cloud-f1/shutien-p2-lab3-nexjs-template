# DBA Migrations — Alembic + SQLAlchemy Patterns

## Two-Layer UUID Design

This project separates UUID handling between models and migrations — understanding this prevents the most common class of bugs.

| Layer | Type | Why |
|-------|------|-----|
| **Models** (`app/models/`) | `GUID` from `app.models.base` | TypeDecorator that converts between Python `uuid.UUID` and DB storage. Handles dialect differences (native UUID on PG, CHAR(36) on SQLite). |
| **Migrations** (`alembic/versions/`) | `sa.Uuid()` | Standard SQLAlchemy 2.0 DDL type. Migrations only define table structure — they don't process values, so GUID's TypeDecorator logic isn't needed. |

**In migrations, use `sa.Uuid()`** — never `sa.CHAR(36)`, `sa.String(36)`, `GUID()`, or `sa.UUID()` (uppercase). The `render_item` hook in `env.py` normalizes autogenerated output to `sa.Uuid()` automatically, but hand-written migrations need manual attention.

## Common Migration Scenarios

### Create a New Table

The most common pattern. Follow this template — it covers UUIDs, timestamps, FKs, indexes, and constraints:

```python
def upgrade() -> None:
    op.create_table(
        "widgets",
        # PK — always sa.Uuid()
        sa.Column("id", sa.Uuid(), primary_key=True),
        # FK — sa.Uuid() + ondelete policy
        sa.Column(
            "owner_id",
            sa.Uuid(),
            sa.ForeignKey("user.id", ondelete="CASCADE"),
            nullable=False,
        ),
        # Data columns
        sa.Column("name", sa.String(100), nullable=False),
        sa.Column("status", sa.String(20), nullable=False, server_default="active"),
        sa.Column("count", sa.Integer(), server_default=sa.text("0")),
        # Booleans — always sa.text("false"/"true")
        sa.Column("is_active", sa.Boolean(), nullable=False, server_default=sa.text("true")),
        # Timestamps — use sa.func.now()
        sa.Column("created_at", sa.DateTime(timezone=True), server_default=sa.func.now()),
        sa.Column("updated_at", sa.DateTime(timezone=True), server_default=sa.func.now()),
        # Constraints
        sa.UniqueConstraint("owner_id", "name", name="uq_widget_owner_name"),
    )
    # Indexes for common query patterns
    op.create_index("ix_widgets_owner_id", "widgets", ["owner_id"])
    op.create_index("ix_widgets_status", "widgets", ["status"])


def downgrade() -> None:
    op.drop_index("ix_widgets_status")
    op.drop_index("ix_widgets_owner_id")
    op.drop_table("widgets")
```

### Add a Column to an Existing Table

```python
def upgrade() -> None:
    op.add_column("user", sa.Column("phone", sa.String(20), nullable=True))
    # For FK columns, add constraint separately
    op.add_column("user", sa.Column("team_id", sa.Uuid(), nullable=True))
    op.create_foreign_key(
        "fk_user_team_id", "user", "teams", ["team_id"], ["id"], ondelete="SET NULL"
    )

def downgrade() -> None:
    op.drop_constraint("fk_user_team_id", "user", type_="foreignkey")
    op.drop_column("user", "team_id")
    op.drop_column("user", "phone")
```

### Data Migration (Backfill)

When you need to populate a new column from existing data:

```python
def upgrade() -> None:
    # 1. Add column as nullable first
    op.add_column("orders", sa.Column("total_cents", sa.Integer(), nullable=True))

    # 2. Backfill from existing data
    conn = op.get_bind()
    conn.execute(
        sa.text('UPDATE orders SET total_cents = CAST(total * 100 AS INTEGER) WHERE total IS NOT NULL')
    )

    # 3. Make non-nullable after backfill
    op.alter_column("orders", "total_cents", nullable=False, server_default=sa.text("0"))

def downgrade() -> None:
    op.drop_column("orders", "total_cents")
```

### Add an Index

```python
def upgrade() -> None:
    op.create_index("ix_places_user_id", "places", ["user_id"])
    # Unique index
    op.create_index("ix_places_slug", "places", ["slug"], unique=True)

def downgrade() -> None:
    op.drop_index("ix_places_slug")
    op.drop_index("ix_places_user_id")
```

## Type Rules Quick Reference

| Column type | Migration type | Default syntax |
|-------------|---------------|----------------|
| UUID PK/FK | `sa.Uuid()` | N/A |
| String | `sa.String(N)` | `server_default="value"` |
| Integer | `sa.Integer()` | `server_default=sa.text("0")` |
| Numeric | `sa.Numeric(P, S)` | `server_default=sa.text("0")` |
| Boolean | `sa.Boolean()` | `server_default=sa.text("false")` |
| DateTime | `sa.DateTime(timezone=True)` | `server_default=sa.func.now()` |
| JSON | `sa.JSON()` | `nullable=True` (no server_default) |
| Text | `sa.Text()` | `nullable=True` |

## Model → Migration Workflow

The full lifecycle when adding a database feature:

```
1. Edit docs/openapi.yaml                    ← spec first (project rule)
2. Create/edit model in server/app/models/   ← use GUID, UUIDMixin, TimestampMixin
3. Import model in server/app/models/__init__.py  ← required for autogenerate
4. Generate migration:
   cd server && uv run python -m alembic revision --autogenerate -m "description"
5. Review generated file                     ← env.py hooks normalize UUIDs
6. Run linter:
   uv run pytest tests/test_migration_lint.py -v
7. Apply migration:
   uv run python -m alembic upgrade head
8. Verify with:
   /athena:dba status
```

### Model Template

When creating a new model, follow this pattern:

```python
from app.models.base import Base, GUID, UUIDMixin, TimestampMixin

class Widget(Base, UUIDMixin, TimestampMixin):
    __tablename__ = "widgets"

    owner_id: Mapped[uuid.UUID] = mapped_column(
        GUID, ForeignKey("user.id", ondelete="CASCADE"), nullable=False
    )
    name: Mapped[str] = mapped_column(String(100), nullable=False)
    is_active: Mapped[bool] = mapped_column(Boolean, default=True)
```

## Foreign Key Ondelete Policies

Choosing the right policy prevents data integrity issues:

| Policy | When to use | Example |
|--------|------------|---------|
| `CASCADE` | Child has no meaning without parent | `portfolios.user_id`, `team_members.team_id` |
| `SET NULL` | Child should survive parent deletion | `places.created_by`, `teams.owner_id` |
| `RESTRICT` | Prevent accidental parent deletion | `billing.user_id` (keep billing history) |

Never omit `ondelete` — the database default varies and leads to unpredictable behavior.

## Autogenerate Hooks

`env.py` has two hooks (added in E63) that fire during `--autogenerate`:

1. **`render_item`**: Normalizes GUID, PG UUID, and sa.Uuid instances to `sa.Uuid()` in output
2. **`compare_type`**: Treats GUID ↔ native UUID as equivalent — prevents spurious ALTER operations

These mean autogenerated migrations are already correct for UUID types. But always review the output and run the linter.

## Pre-Migration Checklist

1. ☐ New model imported in `server/app/models/__init__.py`
2. ☐ Model uses `GUID` from `app.models.base` (not `sa.Uuid()` or `String(36)`)
3. ☐ FK relationships have explicit `ondelete` policy
4. ☐ Run `--autogenerate` (not manual migration) for type safety
5. ☐ Review generated file — check for `sa.CHAR(36)` or bad defaults
6. ☐ Run `pytest tests/test_migration_lint.py` — all pass
7. ☐ Run `alembic upgrade head` — migration applies cleanly
8. ☐ Run `make test-migrations` — PG smoke test passes (if Docker available)

## Debugging Migration Errors

| Error | Cause | Fix |
|-------|-------|-----|
| `DatatypeMismatchError: incompatible types: character and uuid` | Migration uses `sa.CHAR(36)` for FK but target PK is native `uuid` | Change to `sa.Uuid()` |
| `DatatypeMismatchError: column is of type boolean but default expression is of type integer` | `server_default="0"` on Boolean column | Change to `sa.text("false")` |
| `UndefinedColumnError: column X does not exist` | Model has column not yet migrated | Run `alembic revision --autogenerate` |
| `ModuleNotFoundError: No module named 'app'` | Plain `alembic` command (server/ not on sys.path) | Use `python -m alembic` |
| `IntegrityError: violates foreign key constraint` | Inserting child before parent in async SQLAlchemy | Add `await db.flush()` between inserts |
| `Can't sort tables for DROP` | Circular FK | Add `use_alter=True` to one FK, or use `SET NULL` |

## Linter (E62)

`server/tests/test_migration_lint.py` runs automatically in pytest and checks:
- No `sa.CHAR(36)` in any migration
- No `sa.String(36)` in any migration (unless `# noqa: migration-lint`)
- No Boolean columns with `server_default="0"` or `"1"`

Lines containing `# noqa: migration-lint` are exempt (for intentional String fields).
